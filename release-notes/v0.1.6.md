# Dawnmere 0.1.6

This release fixes problems found in reviews before launch. Update with `dawnmere update`, or run the install line again.

## Forgetting

- When you forget something yourself, it is gone for good. That covers typing "forget memory 12" in Claude Code or Codex, running `lflabs-memory forget 12` in Terminal, or using the menu. Its text, its search entries, older versions of it and the facts drawn from it are deleted from the memory file and from its backup copies. The reply tells you what was removed. It cannot be restored.
- When an app forgets something on its own, the memory is hidden right away and deleted for good after 24 hours. Until then you can bring it back with `lflabs-memory restore 12`. An app can only forget memories its own search showed it, and at most 10 a day.
- After a forget, Dawnmere keeps a short fingerprint with no words in it. The fingerprint stops the same thing being saved again from an old conversation.
- If you have Dawnmere set up to read conversations in the background, the forgotten words are held for up to 24 hours. That gives the background job time to find other notes that mention them; then they are erased.
- Memories you forgot in earlier versions still had their text on disk. This update erases that text the first time it runs.

## What apps can save

- An app can no longer save instructions to run downloaded code, delete files, or keep something from you. It can't save words aimed at your assistant's own instructions either.
- Some app saves can't be acted on by your apps without you: rules, instructions, and anything with a command or a link. Your apps can still find them by searching, and they are labelled. To let one through, type "confirm memory 12" and Dawnmere shows its words and a short code. Then type "confirm memory 12 <code>".
- When memory shows your apps a line with a command or a link in it, the line says to check with you first.
- A note saved by Codex or Cursor without a type now goes where those apps can find it again. The reply says where it went and which apps can see it.
- Personal facts stay personal, even when you mention them while working in a code project. That covers your health, family, relationships, money and legal matters.

## Who counts as you

- Some typed commands take effect only once Dawnmere finds those exact words as your latest message in the conversation: "remember that…", "confirm memory", "forget memory" and giving an app more access. They take effect when the reply finishes.
- An app that only names itself (for example, claiming to be Claude Code) now sees work notes only. Claude Code's automatic recall in your prompts still sees everything.
- `dawnmere access <app> everything` and the matching `lflabs-memory clients` commands give an app more access. You must run them in a Terminal window you opened yourself, type the app's name, and click Allow in a dialog. Giving an app less access needs none of this.

## Installing and updating

- Every Python package Dawnmere installs has a pinned version and is checked against a known hash before anything is installed. If a check fails, nothing is installed. If an update fails partway, the update puts the old version back or leaves Dawnmere uninstalled, never a half-checked copy.
- The Claude Code plugin comes from the same release as everything else, not from the latest code on GitHub.
- Downloads retry when GitHub is slow or briefly down. A model that fails to download no longer stops setup; `dawnmere doctor` shows it and `dawnmere setup --models` finishes it.
- Without Node.js, your apps can't use memory's tools. Setup and `dawnmere doctor` now say so plainly instead of reporting success.
- If the `dawnmere` command won't be found in new Terminal windows, setup and doctor give one clear line to add to `~/.zshrc`. Claude Code's hooks no longer depend on your PATH.
- Installing without a terminal (for example `curl … | sh` in a script) no longer changes your apps' settings unless you pass `--yes`.
- Uninstall now says that uv and its Python stay on your Mac, and how to remove them. It removes the files and plugin data it added and leaves your Claude Code settings as they were.
- Dawnmere's background jobs no longer let Claude Code send its own usage data while they run.

## Privacy, in one place

- Two parts of Dawnmere can reach the internet. The model you chose for background reading: your Claude plan through Claude Code, or the Anthropic API with your key. And GitHub, for releases and updates, plus open pull requests for the project you're working in if you use GitHub's `gh` tool.
- Background reading sends the model your finished Claude Code conversations and the few related memories it needs to read them.
