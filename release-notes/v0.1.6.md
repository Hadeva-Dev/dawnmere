# Dawnmere 0.1.6

This release fixes problems found in reviews before launch. Update with `dawnmere update`, or run the install line again.

## Forgetting

- When you forget something yourself, it is gone for good. That covers typing "forget memory 12" in Claude Code or Codex, running `lflabs-memory forget 12` in Terminal, or using the menu. Its text, its search entries, older versions of it and the facts drawn from it are deleted from the memory file and from its backup copies. The reply tells you what was removed. It cannot be restored.
- When an app forgets something on its own, the memory is hidden right away and deleted for good after 24 hours. Until then you can bring it back with `lflabs-memory restore 12`. An app's forget tool can only forget memories its own search showed it, at most 10 a day; a forget an app runs in its own shell is held the same way.
- After a forget, Dawnmere keeps a short fingerprint with no words in it. The fingerprint stops the same thing being saved again from an old conversation.
- If you have Dawnmere set up to read conversations in the background, the forgotten words are held for up to 24 hours. That gives the background job time to find other notes that mention them; then they are erased.
- Memories you forgot in earlier versions still had their text on disk. This update erases that text the first time it runs.

## What apps can save

- An app can no longer save instructions to run downloaded code, delete files, or keep something from you. It can't save words aimed at your assistant's own instructions either.
- Notes an app saves on its own are kept for search, labelled, and reach other apps' prompts only after you confirm them (`lflabs-memory held`). Your apps can still find them by searching. To confirm one, type "confirm memory 12" and Dawnmere shows its words and a short code. Then type "confirm memory 12 <code>".
- This also applies to notes saved before this update, including Claude Code memory files Dawnmere imported: they stay searchable and wait for your confirm (or `lflabs-memory trust`). `lflabs-memory held` lists every waiting note with the exact "confirm memory" line to type, and `dawnmere doctor` says how many there are.
- When setup imports the notes Claude Code keeps, it asks you once, in a macOS dialog, whether to trust them as your own. With `--yes`, or if you cancel, they wait for your confirm, and setup says how.
- Once a day, a new Claude Code session says how many notes your apps saved are waiting for you.
- What you save yourself ("remember that…", in any language) still reaches all your apps, once your reply finishes.
- When an app saves something you already said yourself, your memory stays yours: it keeps your words and still reaches your prompts.
- `lflabs-memory add` typed in Terminal asks in a dialog whether to keep the line as your own words; without your click it's kept like any app's save. `lflabs-memory trust` does the same for memories you choose, with one dialog.
- `dawnmere import FILE` adds the memories from an export file, skipping ones you already have; they are saved as of unknown origin, and if the file says some are your own words, a macOS dialog asks you once whether to trust them as yours.
- Running setup again keeps the name you gave it, moves Codex's and Cursor's connector to the new version, and on an install that used Claude Code's settings file instead of the plugin, switches to the plugin without leaving the hooks there twice.
- When memory shows your apps a line with a command or a link in it, the line says to check with you first.
- A note saved by Codex or Cursor without a type now goes where those apps can find it again. The reply says where it went and which apps can see it.
- Personal facts stay personal, even when you mention them while working in a code project. That covers your health, family, relationships, money and legal matters, in English, Chinese and Japanese.

## Other languages

- "remember that…" works with full-width punctuation (，！？), and Chinese and Japanese phrasings save too: 记住：, 请记住，, 记一下：, 覚えておいて：, メモして：, これを覚えて：.
- With background reading on, a prompt in Chinese, Japanese, Korean, Russian or any other non-Latin script is now translated for search, like other non-English prompts. That means more model calls for people who write in those languages.

## Who counts as you

- "confirm memory" and "forget memory" take effect when the reply finishes, once Dawnmere finds those words as your latest typed message; a "remember that…" is saved at once and counts as your own words then.
- Typing "let Cursor see everything" (or any other way of giving an app more access) no longer changes anything by itself. The reply gives you the `dawnmere access` command to run in Terminal, where you confirm it in a dialog. Typing that an app should see less still works at once.
- Claude Code's and Claude Desktop's memory tools, and any app that only names itself, now see work notes only. Claude Code's automatic recall in your prompts still sees everything.
- `dawnmere access cursor everything` and the matching `lflabs-memory clients` commands give an app more access. You must run them in a Terminal window you opened yourself, type the app's name, and click Allow in a dialog. Giving an app less access needs none of this.

## Installing and updating

- Every Python package Dawnmere installs has a pinned version and is checked against a known hash before anything is installed. If a check fails, nothing is installed. If an update fails partway, the update puts the old version back or leaves Dawnmere uninstalled, never a half-checked copy.
- The Claude Code plugin comes from the same release as everything else, not from the latest code on GitHub. Running the install line again on an older install moves the plugin to this release; restart Claude Code afterwards.
- Updating from 0.1.5 with `dawnmere update`: 0.1.5's updater installs without these checks, so 0.1.6 checks every dependency against its hashes right after the update and removes Dawnmere if one doesn't match. The new version has already started once by then, so for the strongest guarantee, update by running the install line instead.
- Downloads retry when GitHub is slow or briefly down. A model that fails to download no longer stops setup; `dawnmere doctor` shows it and `dawnmere setup --models` finishes it.
- Without Node.js, your apps can't use memory's tools. Setup and `dawnmere doctor` now say so plainly instead of reporting success.
- New Terminal windows find the `dawnmere` command: the installer adds one marked line to `~/.zprofile` and tells you, and uninstall takes it out again. Claude Code's hooks no longer depend on your PATH.
- On a Mac without Apple's Command Line Tools, the "install developer tools" window no longer pops up: not from the installer or `dawnmere update` setting up Python, and not from memory, which never runs `git` there and recognises your projects by their `.git` folder. Reinstalling no longer reinstalls Python when it is already there.
- On a first setup the service can take up to a minute to load its models. Setup now waits, says it is still starting, and retries once; if it still doesn't start, `~/Library/Logs/LF Labs/memory.log` says why.
- Setup's self-check saves a random phrase and deletes only the memory it made itself, never an older one.
- Running setup again keeps your other settings in `config.toml`, such as the daily call limit.
- Signed out of Claude Code, `dawnmere doctor` warns that background reading waits, instead of failing; recall and remember still work.
- Right after a restart, `dawnmere doctor` says the service is still loading instead of warning about a slow first recall. Setup's self-check waits for the service to be ready.
- Installing without a terminal (for example `curl … | sh` in a script) no longer changes your apps' settings until you run `dawnmere setup` (or `dawnmere setup --yes`).
- Uninstall now says that uv and its Python stay on your Mac, and how to remove them. It removes the files and plugin data it added, including the connector's socket, lists each file once, and leaves your Claude Code settings as they were.
- Dawnmere's background jobs no longer let Claude Code send its own usage data while they run.

## Privacy, in one place

- Your memory is stored on this Mac. Dawnmere sends nothing to LF Labs and has no usage tracking.
- With background reading on, these go to the model provider you chose (your Claude plan through Claude Code, or the Anthropic API with your key):
  - your Claude Code conversations, after every 6 of your messages and when a session goes quiet;
  - up to 8 related memories, which can include notes Codex or Cursor saved;
  - memories waiting to be filed into sections;
  - a prompt not in English, from any app, to translate it for search;
  - for up to 24 hours, the words of something you forgot, so other notes that mention it can be found and deleted.
  At most 200 calls a day. With no model set up, none of this is sent.
- Dawnmere also contacts GitHub, for releases and updates and, if you're logged in to GitHub's `gh` tool, the open pull requests of the project you're working in. Your apps contact npm when they start memory's connector. The installer and `dawnmere update` contact PyPI for Python packages, each checked against a pinned hash.
