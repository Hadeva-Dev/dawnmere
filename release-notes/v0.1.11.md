# Dawnmere 0.1.11

Update with `dawnmere update`, or run the install line again.

- **An app set to see nothing gets nothing.** A Codex or Cursor you had once allowed more (`dawnmere access codex everything`) and later set to `nothing` still got work notes in its prompts, though its memory tools found nothing. Its prompts now get nothing too. If you never widened an app, this did not affect you.
- **Uninstall no longer costs you your own app file.** If you uninstalled and kept your memory, then wrote your own file for an app (say `~/.cursor/mcp.json`), then ran setup and uninstalled again, uninstall could delete that file or rewrite it instead of putting it back. Uninstall now forgets what it undid, so the next setup starts from the files as they are.
- **A work note you type reaches Codex and Cursor at once.** "Remember that we deploy on Fridays" typed in Claude Code in a project could stay hidden from work-only apps for up to a minute, or for good with the memory service stopped. They can recall it right away now; saving takes about a second longer when the service is stopped. A note that has no sensitivity label yet also stays out of a work-only app's session start, your own typed notes included, so a health or money note is not shown there before it has been checked.
- **A no to importing Claude Code's notes is kept.** Say no to setup's question (or pass `--no-import`) and Dawnmere no longer reads `~/.claude/projects/*/memory` in by itself later. The answer is written to config.toml (`claude_notes` under `[privacy]`), and running setup again keeps it. `lflabs-memory import` still reads them when you ask.
- **Terminals that are not UTF-8.** With a GB2312, Shift-JIS or Latin-1 locale, recall and typed saves broke, `dawnmere held` and `dawnmere search` could end in a traceback, and so could `dawnmere doctor` with a non-English name in config.toml. All of these work now.
- **`dawnmere access` alone lists your apps** and what each one sees. `nothing-personal` is no longer offered: in a plain install it hid the same notes as `work` while the message said otherwise. Typed anyway, it is taken as `work` and says so. A name that is no app (`dawnmere access bogusapp work`) is refused instead of making a new client.
- **`dawnmere add` and `dawnmere search` read every word.** `dawnmere add buy milk tomorrow` saved "buy"; it saves the whole line now. A misspelled option, or one missing its value, is refused with the usage line and nothing is saved.
- **`dawnmere add` says when the note is held.** A note added from a script, or without Allow in the dialog, is kept out of prompts until you confirm it. The line now says so and points to `dawnmere held`.
- **Exit codes.** `dawnmere forget` and `dawnmere restore` exit 1 when nothing was done, and `restore` on a memory that was never forgotten says so instead of "restored".
- **No empty store before setup.** After an uninstall that deleted your memory, `dawnmere doctor` or `dawnmere held` brought the data folder back with an empty store. `held`, `search`, `add`, `forget`, `restore` and `trust` now say Dawnmere is not set up yet, and `doctor` leaves the folder alone.
- **Setup's speed line** times the second prompt after one that warms things up, so a new install is not told recall is slow because of its very first prompt.
- **Docs.** The README (English, 简体中文, 日本語) says the Claude Code plugin route needs git, what widening an app changes, and that a Terminal `add` is held until you allow it. `/dawnmere:setup` no longer installs a second copy over a Homebrew install that has not been set up.
- **Connector 0.1.2.** The small piece each app launches is now `dawnmere-connector@0.1.2` on npm. Its npm page and its MCP Registry name point to LF-Labs-Inc, and it reports its server name as `dawnmere`. Setup and `dawnmere update` move your apps to it.
